Sandbox execution plane rendered with separate controller and executor namespaces.

Before install, replace every example CIDR, digest, and endpoint and provide all referenced TLS,
database, NATS, and workload-identity authorities. The chart creates no credentials, RBAC
Role/RoleBinding, or attestor Service.

This Phase 1 composition contains the controller, restricted WASI Executor, and node attestor.
Deferred execution backends and persistent local protocol sessions are intentionally absent. The
second first-release execution lane is added only when its Phase 3 implementation and qualification
gates pass.

The attestor is the only workload with hostPID. The WASI Executor remains non-root, receives no
Kubernetes API token, and mounts only its immutable configuration, credentials, temporary storage,
and the attestor socket. Label execution nodes with the NodeRestriction-protected
`insight.platform.node-restriction.kubernetes.io/sandbox-wasi` and `sandbox-attestor` keys for the
same supported Linux architecture. Use distinct Secret objects for every workload TLS identity and
for NATS credentials. Verify the configured scheduler and DaemonSet-controller identities against
authenticated cluster audit identity before installation.
