# 0.2.0 开发预览

本版本提供重构后的持久 Agent 执行架构。PostgreSQL 保存当前业务状态，独立 Worker 执行编排、模型、Context、Capability、
Artifact 和维护工作；消息只用于唤醒与已提交投影。CLI 与 Console 使用同一个 Rust/WASM 作者编译核心。

这是全新安装版本。请使用新项目目录和空数据库；不支持旧 schema、迁移链、旧数据或旧开发进程记录。
项目目录、依赖容器与 volume 按完整 Tenant UUID 隔离，验证工具在退出时清理自己创建的资源。

## 安装精确版本

从 [v0.2.0 发行页](https://github.com/yimuu/insight-agent-platform/releases/tag/v0.2.0) 选择与系统和 CPU 对应的 archive：

| 系统 | CPU | archive 后缀 |
| --- | --- | --- |
| macOS | Apple Silicon | `aarch64-apple-darwin.tar.gz` |
| macOS | Intel | `x86_64-apple-darwin.tar.gz` |
| Linux | ARM64 | `aarch64-unknown-linux-gnu.tar.gz` |
| Linux | x86_64 | `x86_64-unknown-linux-gnu.tar.gz` |

每个文件名以 `insight-0.2.0-` 开头。下载后核对发行资产中的 checksum 和 GitHub provenance，解压到新的目录，
再将其中的 `insight` 放入自己的 PATH。首次启动会校验签名 ReleaseBundle，并按精确摘要取得运行程序。

以下预构建启动步骤适用于 Linux。macOS archive 支持 CLI 安装、版本、更新和诊断；本地服务需要 Rust 与本仓库 checkout，
从 checkout 中执行 `insight dev --path ./my-agent-020 --from-source` 后才能使用本地 Agent 命令。macOS 不支持默认或离线预构建启动，
CLI 会在拉取 runtime 或写入运行配置前明确拒绝。`doctor.ready` 仅表示报告所列依赖检查通过。

```bash
insight version --json
insight doctor --json
insight init --path ./my-agent-020 --name my-agent-020
insight dev --path ./my-agent-020
insight agent publish --path ./my-agent-020 --file ./my-agent-020/agent.yaml
insight agent run my-agent-020 --path ./my-agent-020 --input '{"message":"hello"}'
```

预览版使用精确版本 URL。`update check` 查询稳定版 latest，不用于发现本开发预览；已安装兼容当前签名协议的 CLI
可显式执行 `insight update apply --version 0.2.0`。更新 CLI 不会重建旧项目或转换数据。

## 验证与使用范围

发行必须经过四平台 CLI 构建、不可变多架构镜像、签名候选、真实开发 profile 性能验证与完整 Kind 产品旅程，
最后把资格证据纳入重新签名的 ReleaseBundle。失败的候选不发布为可安装发行版，GitHub 的 prerelease 标记也不放宽这些门槛。

这些证据覆盖开发环境，不代表生产容量、持续负载、跨故障域恢复或 GitOps 投产资格。具体边界见
[开发阶段验证状态](../qualifications/README.md)和[运维说明](../current/operations.md)。

Model、Context 等 feature 安装相应运行角色。接入实际服务仍需部署者配置 provider、凭证、网络授权及精确资源绑定；
启用 feature 本身不构成真实模型调用成功的证据。
