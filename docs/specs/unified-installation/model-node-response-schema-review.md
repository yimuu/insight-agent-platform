## Evidence and owning decision

The document-review FullPlan has an intermediate ModelLoop producing a draft and a later HumanTask
producing a review. Its Agent output combines both. Before this repair the PostgreSQL controller used
the Agent output schema for both the model's textual response instruction and canonical response
contract. It would ask the model to produce a human review before the HumanTask had occurred.

The exact ModelLoop output port and RuntimePlan's frozen schema documents own the intermediate
response. The Agent interface continues to own only the external input/output contract. Reuse the
existing Plan schema representation and checked ClosedValueSchema-to-ClosedJsonSchema conversion;
do not introduce an alternate schema registry or broaden ModelResponseContract to scalar values.
Plan validation rejects non-object ModelLoop output schemas before publication, just as the
existing HumanTask response boundary requires an object. Other internal ports keep their existing
scalar/array support.

The Plan owner exposes one fallible model-node response-schema lookup. The scheduler uses the
already verified, exact materialized Plan to pass that schema into its internal admission request.
Admission validates the schema and its equality with the node output digest. Canonical model
request construction freezes this schema. AgentContract attribution retains the Agent's original
interface, contract, input and output digests; the model response digest and optional textual JSON
schema belong to the existing PlanNodeInstruction block, attributed to the frozen Plan revision.
The ordinary source map and prompt byte/token limits charge that complete block before dispatch.
The basic Model safety instruction must name this actual Plan-node response instruction rather
than the Agent contract. New bootstrap declarations receive their natural new content digest;
existing frozen Policies and installations are not rewritten.

The PostgreSQL orchestration command repeats the comparison against the exact Plan inside the
existing fenced transaction before creating a ModelTurn or reserving its quotas. Continuations
retain the complete original response contract. A malformed or mismatched schema fails without provider I/O,
new ModelTurn, quota changes or a second current-state authority. ModelResponseContract validation
also requires any structured schema's canonical digest to equal its declared output digest.

## Identity, transactions and recovery

This changes interpreter output semantics and narrows accepted ModelLoop plans. The IR wire shape
remains v6; its semantic profile is v3 and the shared native/WASM compiler semantic version is 7.
Previous workers cannot claim new plans with the old semantic capability. Compiler evidence is
regenerated by the shared owner; digest outputs are not hand-edited.

No public DTO shape, SQL schema, table, lease, event, Receipt, quota algorithm, authorization or
transport changes are required. Model response digests remain naturally part of the existing
canonical request identity. Already frozen installations, deployments, attempts and failures are
not repaired or replayed. Current authorization and original CAS/deadline rules remain mandatory.
The existing bounded schema and prompt budgets bound the additional attribution content; there is
no extra body store, background work or external call.
